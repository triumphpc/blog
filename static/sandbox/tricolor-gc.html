    Why it works this way — notes on Go's GC

    01

    Go does not stop the world for the whole mark phase: markers run alongside the program, and correctness is held by the write barrier. It enforces the invariant that a black object cannot quietly acquire a pointer to a white one — the moment such a write happens, the white object is shaded grey.

    02

    Objects allocated while a cycle is in flight are born black: they were just created, there is nothing to scan inside them, and shading them grey would keep the marker running in circles.

    03

    Mark assist: a goroutine that allocates memory must do marking work proportional to what it allocated. Otherwise one goroutine would allocate faster than the rest can mark.

    04

    Unlike reference counting, tricolor marking happily collects garbage cycles — the starting heap has a pair F ⇄ G for exactly that: run to the sweep and check.
